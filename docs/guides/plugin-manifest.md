# Plugin manifest and layouts

English | [Русский](plugin-manifest.ru.md)

Every Antigravity plugin is anchored by a flat `plugin.json` manifest and
convention-based component directories at the plugin root.

## Unified loader across CLI, App, and IDE

In Antigravity `1.5.17+`, all three Google Antigravity surfaces share one
unified Go plugin loader and schema:

- **`agy` CLI (`1.5.17+`)** — runs the core engine, `agy plugin validate`, and
  the `--hub` daemon.
- **`Antigravity.app` (`2.35.1+`)** — bundles a matching Go language server
  with identical hook/plugin descriptors.
- **`Antigravity IDE` (`2.7.0+`)** — delegates directly to `agy --hub`.

There is only **one** plugin format to build, validate, and ship.

## Manifest precedence and component root

Antigravity looks for a plugin manifest in three locations, highest priority
first:

1. `<plugin>/.antigravity-plugin/plugin.json` *(highest)*
2. `<plugin>/.gemini-plugin/plugin.json`
3. `<plugin>/plugin.json` *(root — default generated by `create.mjs`)*

Two critical rules:

- **Never keep two manifests** in the same plugin — shadowed lower-priority
  manifests emit a warning and fail `agy plugin validate --strict`.
- **Components ALWAYS live at the plugin root** (`skills/`, `rules/`, `agents/`,
  `hooks.json`, `mcp_config.json`, `sidecars/`, `assets/`), even when the
  manifest itself lives inside `.antigravity-plugin/plugin.json`.

You can scaffold either layout with `create.mjs`:

```bash
node scripts/create.mjs my-plugin                                 # root plugin.json
node scripts/create.mjs my-plugin --manifest-layout dot-antigravity
```

## Strict JSON vs JSONC

While the runtime loader tolerates JSONC comments and trailing commas,
**`agy plugin install` requires strict JSON** and `agy plugin validate --strict`
fails on JSONC syntax. Always write strict JSON in `plugin.json` (and
`hooks.json`).

## Accepted `plugin.json` fields

```json
{
  "name": "my-plugin",
  "displayName": "My Plugin",
  "version": "1.0.0",
  "description": "One-sentence summary of what the plugin adds to Antigravity.",
  "logo": "assets/logo.svg",
  "suggestedPrompts": [
    "Review this repository with my-plugin",
    "Run /my-plugin-help"
  ],
  "author": {
    "name": "Your Name",
    "url": "https://github.com/your-org"
  },
  "homepage": "https://github.com/your-org/my-plugin",
  "repository": "https://github.com/your-org/my-plugin",
  "license": "MIT",
  "keywords": ["antigravity", "plugin"],
  "category": "Developer Tools"
}
```

| Field | Format & constraints |
|---|---|
| `name` | Strict lowercase kebab-case (`^[a-z0-9]+(?:-[a-z0-9]+)*$`). Global unique key — duplicate names silently drop one plugin. |
| `displayName` (`display_name`) | Human-readable UI title. Avoid a leading `"Antigravity"` prefix for Marketplace listings. |
| `version` | SemVer (`MAJOR.MINOR.PATCH`). Required for Marketplace submission. |
| `description` | 1–2 sentences (~120–160 chars for clean Marketplace cards). |
| `logo` | Plugin-relative `.svg`, `.png`, `.jpg`, `.jpeg`, or `.webp` (square `>=128×128`, ~10% transparent padding, **never** inside a dot-prefixed directory such as `.github/`), or an `https://` URL on a Google domain. Omitting `logo` emits a validator `note`. |
| `suggestedPrompts` (`suggested_prompts`) | Up to **3** non-empty starter prompt chips (4+ or empty strings warn). |
| `author` | String (`"Your Name"`) **or** `{ "name": "...", "email"?: "...", "url"?: "https://..." }`. |
| `homepage` | `https://` URL. |
| `repository` | `https://` URL string **or** `{ "type": "git", "url": "https://..." }`. |
| `license`, `keywords`, `category` | SPDX string, `string[]`, non-empty category string. |
| `disabled` | Boolean (`true` ships the plugin turned off until the user enables it). |
| `skills` | Optional relative path or `string[]` of extra skill directories. |
| `extensions` | Optional `extensions["com.google.antigravity"].contextProviders`. |

## Dead keys that fail `--strict`

Do **not** include legacy or external manifest fields — every one of these emits
`unknown field "<key>" is ignored` and fails `agy plugin validate --strict`:

- `interface` (replaced by flat `displayName`, `logo`, `suggestedPrompts`)
- `rules`, `hooks`, `agents`, `commands`, `mcpServers`, `sidecars` (auto-discovered
  from root folders/files, not declared in `plugin.json`)
- `variables` (belongs inside individual servers in `mcp_config.json`)
- `contextProviders`, `bundleMembers`

## Enablement, discovery priority, and JSON registries

Antigravity discovers customizations in strict priority order (high -> low):

1. **Workspace discovery:** `.agents/` (plus `.agent/`, `_agents/`, `_agent/`)
   walking up from CWD to repo root — both `.agents/plugins/<name>/` and flat
   `.agents/{skills,rules,agents,hooks.json,mcp_config.json}`. In headless
   `agy -p`, pass `--add-dir <project>`.
2. **Workspace declared JSON registries:** `.agents/{plugins,skills,rules,agents,sidecars}.json`
   (paths cannot escape repo root via `../`, absolute paths, or symlinks).
3. **Global discovery:** `~/.gemini/config/plugins/<dir>/` (plus
   `~/.gemini/config/{skills,rules,agents,hooks.json,mcp_config.json}` and
   `~/.agents/skills/`).
4. **Built-in customizations** and **global declared JSON registries**.

**Enablement state (`installed_version.json` is obsolete):**
- Any folder under `~/.gemini/config/plugins/<dir>/` with a valid `plugin.json`
  auto-loads without needing `installed_version.json`.
- Active/disabled toggles live in `~/.gemini/config/config.json` under
  `plugins.<dir>.enabled` — keyed by the **install directory name** (not
  `plugin.json`'s `name`) and always overriding `"disabled": true`.
- Deep links use `customization://<dir>`.

## Sidecars (`sidecars/`)

Plugins can run background worker processes via
`sidecars/<id>/sidecar.json` (or root `sidecars.json`), automatically
namespaced as `<plugin>/<id>`:

```json
{
  "command": "node",
  "args": ["worker.mjs"],
  "restart_policy": "on-failure",
  "display_name": "My Worker",
  "description": "Background helper process."
}
```

Every sidecar must declare **either `command` or `builtin`** (for example
`"builtin": "schedule"`), never both, and a valid `restart_policy` (`always` |
`on-failure` | `never`). Scaffold a working example with
`create.mjs my-plugin --with-sidecar`.
