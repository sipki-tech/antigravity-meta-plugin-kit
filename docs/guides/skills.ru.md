# Скиллы

[English](skills.md) | Русский

Скиллы — это пакеты инструкций по запросу, которые почти не тратят контекст до
активации: при старте сессии Antigravity индексирует только `name` и
`description`, а тело `SKILL.md` загружает лишь когда задача совпадает или
пользователь вызывает `/<skill-name>`.

## Структура каталогов и загрузка

Каждый скилл хранится в собственной папке kebab-case внутри `skills/`:

```text
skills/
└── my-plugin-example/
    ├── SKILL.md           # обязательно — YAML frontmatter + инструкции
    ├── scripts/           # опциональные вспомогательные CLI/скрипты
    ├── resources/         # опциональные шаблоны, фрагменты промптов, схемы
    ├── references/        # опциональные длинные справочники по запросу
    └── examples/          # опциональные рабочие примеры
```

Antigravity также поддерживает дополнительные пути скиллов через поле `skills` в
`plugin.json` или корневой реестр `skills.json` (`{"entries": [{"path": "..."}]}`).
Имя `name` во frontmatter обязано точно совпадать с именем папки (kebab-case).

## Frontmatter и многострочный YAML

Antigravity `1.5.17` разбирает полноценный YAML frontmatter в `SKILL.md`,
включая многострочные свёрнутые (`>`, `>-`, `>+`) и буквальные (`|`, `|-`, `|+`)
скаляры:

```markdown
---
name: my-plugin-example
description: >-
  Guides deployment checklists for Acme services. Use when preparing a release,
  verifying staging rollouts, or writing rollback steps. Don't use for local
  unit tests or database schema migrations.
metadata:
  icon: rocket
---

# Deployment checklist
...
```

Поддерживаемые поля frontmatter:

| Поле | Назначение |
|---|---|
| `name` | Обязательный идентификатор kebab-case, совпадающий с папкой и slash-командой `/<name>`. |
| `description` | Обязательное описание для маршрутизации в индексе `<skills>` системного промпта. |
| `disable-model-invocation` | Boolean. При `true` скилл работает **только как slash-команда** (`/<name>`) и никогда не вызывается моделью сам. |
| `disable-slash-command` | Boolean. При `true` модель может подхватить скилл сама, но `/<name>` скрыт из меню slash-команд. |
| `metadata.icon` / `metadata.logo` | Опциональные метаданные значка в UI. |

## Как писать сильные триггеры

Поле `description` — это **вся поверхность маршрутизации** для автоматической
активации скилла. Пишите его как чёткий классификатор, а не рекламный слоган:

1. **Начните с конкретной возможности** (одно короткое предложение).
2. **Добавьте позитивные триггеры:** `"Use when ..."` с точными файлами,
   артефактами, ошибками или фразами пользователя.
3. **Добавьте негативные границы:** `"Don't use for ..."` для смежных задач,
   которые относятся к другим скиллам или обычной разработке.

`lint.mjs` падает с `FAIL`, если в `description` обычного скилла нет триггеров
(и автоматически пропускает эту проверку для slash-скиллов с
`disable-model-invocation: true`).

## Управление вызовом: `disable-model-invocation` и `disable-slash-command`

- **Экспертные и справочные скиллы** (по умолчанию): не задавайте оба флага —
  скилл доступен и модели, и пользователю через `/<name>`.
- **Детерминированные `/slash`-команды и обёртки субагентов:** ставьте
  `disable-model-invocation: true`. Это официальная замена `agy 1.5.17+` для
  мёртвых `workflows/*.md` и канонический способ выдать субагента как `/<cmd>`
  (см. [Субагенты](agents.ru.md)).
- **Фоновые скиллы:** ставьте `disable-slash-command: true`, если скилл нужен
  только модели и не должен засорять меню `/`.

## Лимит 24 000 байт и постепенное раскрытие

Antigravity ограничивает **тело `SKILL.md` 24 000 байтами** (без учёта
frontmatter). Файлы больше порога выдают warning в `agy plugin validate
--strict` и **тихо обрезаются** в рантайме.

Держите `SKILL.md` компактным (~50–200 строк) и используйте постепенное
раскрытие:

- В `SKILL.md` держите дерево решений, инварианты и точные команды.
- Длинные чеклисты, схемы и таблицы выносите в `references/*.md` с указанием
  читать их через `read_file` только на нужной ветке.
- Детерминированную проверку или генерацию выносите в `scripts/*.mjs`, чтобы
  агент вызывал одну команду вместо пересказа логики прозой.

## Встроенные скрипты и шаблоны промптов

- Ссылайтесь на соседние файлы чистыми относительными путями внутри `SKILL.md`
  (например `scripts/check.mjs` или `resources/prompt-template.md`) — агент
  разрешает их относительно пути папки скилла из индекса `<skills>`.
- Переиспользуемые структурированные промпты храните в `resources/` с явными
  XML-тегами (`<context>`, `<constraints>`, `<output_format>`), чтобы модель
  чётко отделяла шаблон от пользовательского ввода.
